# Task 11 · anakata-rms · App shell
**Repo:** anakata-rms · **Sprint:** 0 (read `../anakata-api/docs/sprints/sprint-00/README.md` first)
**Needs:** task 06 (API health + CORS) and task 10 (`anakata-ui` v0.1.0).

## Goal
The RMS runs on port **3001** as an SPA (`ssr: false`), extends the layer, and shows the RMS prototype's shell: sidebar, top bar and navigation, with placeholder pages.

## Read first
- `.cursor/rules/anakata-core.mdc` and `.cursor/rules/nuxt-app.mdc`
- The RMS prototype. Its navigation is **generated by JavaScript**: read the script for the exact groups, labels, glyphs, counters and order, plus the `aside`, `.nav` and top-bar CSS.
- RMS screenshots
- `../anakata-api/docs/requirements/01-functional-spec.md` (the module list)
- `../anakata-api/docs/sprints/ROADMAP.md` (the sprint that builds each module)

## Do — wire the layer (same in all three apps)
1. Remove the starter's own CSS content and its `css` entry. Delete the starter's demo pages and components.
2. `@nuxt/ui` and `tailwindcss` at **the same versions as anakata-ui**.
3. `nuxt.config.ts`:
   ```ts
   extends: [
     process.env.ANAKATA_UI_LOCAL
       ? '../anakata-ui'
       : ['github:<org>/anakata-ui#v0.1.0', { install: true, auth: process.env.GITHUB_TOKEN }],
   ],
   modules: ['@nuxt/ui'],
   runtimeConfig: { public: { apiBase: 'http://localhost:8000' } },
   ```
   Also set the dev server port (see below).
4. `.env.example` with `ANAKATA_UI_LOCAL=1`, `NUXT_PUBLIC_API_BASE=http://localhost:8000` and `GITHUB_TOKEN=`, each explained in a comment.
5. **API status indicator.** A small `ApiStatus` component styled like the prototype's small mono status text, placed in the footer or top bar. It calls `GET /api/health` through `useApi()` and shows `API · OK` or `API · DOWN`. It proves the base URL and CORS work.
6. **Tooling:**
   - `pnpm lint`, `pnpm typecheck` and `pnpm build` pass.
   - `.github/workflows/ci.yml`: install (layer pulled with the `GITHUB_TOKEN` secret), lint, typecheck, build.
   - `README.md`: running locally, env vars, the CI secret.

## Do — the RMS shell
7. `ssr: false`, dev port **3001**.
8. **Layout, exactly as the prototype:**
   - Left `aside`: 220px, bg `--forest`, 1px `--hair` right border, 24px vertical padding, with the brand/wordmark block and the navigation.
   - Main area with a top bar containing:
     - the page title (prototype h1 style)
     - a slot for the date-range filter
     - a **role switcher placeholder** showing Admin / Manager / Sales Exec as in the prototype (it does nothing until Sprint 1)
     - `AnkThemeToggle`
     - the **＋ New Reservation** button
9. **Navigation**, exactly as the prototype renders it. Expected from doc 01:
   - RESERVATIONS: Booking Requests, Calendar, Yacht Layout, Bookings
   - COMMERCIAL: Payments & Revenue, Rates & Promotions, B2B & Agent Portal, Contacts In
   - OPERATIONS: Holds & Waitlist, Refund Approvals, Internal Blocks, Documents & Manifests, Guest Experience
   - BOOKING ENGINE: Itineraries, Departures, Offers, Engine Settings, Engine Map
   - ADMIN: Permissions, Business Rules

   **The prototype is authoritative**; report every difference from doc 01. Hover and active states as in the prototype (`.nav a`: padding 10px 22px, `--iv62`, 13px, 2px left border).
10. **Routes.** One per nav item, grouped by section (e.g. `/reservations/booking-requests`, `/commercial/rates`). Each renders an `AnkPanel` empty state with the page title and "Coming in Sprint N" (N from ROADMAP.md). `/` redirects to the page the prototype opens on.
11. Navigation labels go through i18n (`en.json`).
